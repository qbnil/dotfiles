# qbnil dotfiles

XDG-first Arch Linux configuration for my vxwm desktop, managed with GNU Stow.

## Layout

- `config/` — selected portable configuration under `~/.config`.
- `bin/` — personal scripts from `~/.local/bin`.
- `share/` — the retained part of `~/.local/share`, including complete vendored source trees for dmenu, slock, st-terminal, vxwm and zlstatus, plus selected scripts and local assets.
- `bootstrap/` — package manifests and the dry-run installer.

The source trees are owned by this repository: nested upstream `.git` directories, patch files and compiled output are not needed. Their modified source files, configs and vxwm keybindings are already included.

## What Git ignores

The only general exclusions are credentials/private keys and files that are generated by compiling the vendored programs. Build artifacts can always be recreated:

```text
*.o, *.so, *.a
.zig-cache/
zig-out/
vxwm, dmenu, slock, st, nsxiv, vcompmgr
```

Credentials remain local and must never be committed:

```text
~/.config/shell/secrets.sh
~/.config/ghgrab/config.json
~/.config/anthropic/credentials/
~/.config/ssh/
```

Everything else present in the repository is intended to be committed. Personal data is therefore local in this working tree but will be included if you deliberately `git add` it; review `git status` before staging.

## New-machine setup

### 1. Install the base packages

Clone the repository first, then review and install the package lists:

```sh
git clone git@github.com:qbnil/dotfiles.git ~/dotfiles
cd ~/dotfiles
sudo pacman -S --needed - < bootstrap/packages-native.txt
# Install the entries in bootstrap/packages-aur.txt with your AUR helper.
```

### 2. Prepare XDG directories and secrets

```sh
mkdir -p ~/.config ~/.local/bin ~/.local/share ~/.local/state ~/.cache
cp config/.config/shell/xdg-env.sh.example ~/.config/shell/xdg-env.sh
chmod 600 ~/.config/shell/xdg-env.sh
$EDITOR ~/.config/shell/xdg-env.sh
```

Add API keys and other machine-only values only to the local file. Do not add that file to Git.

### 3. Preview Stow

Back up any existing files first, then inspect the proposed links:

```sh
backup="$HOME/dotfiles-backup-$(date +%Y%m%d-%H%M%S)"
mkdir -p "$backup"
cp -a ~/.config "$backup/" 2>/dev/null || true
cp -a ~/.local/bin "$backup/" 2>/dev/null || true
cp -a ~/.local/share "$backup/" 2>/dev/null || true

stow --target="$HOME" --no-folding --simulate --verbose config bin share
```

### 4. Apply Stow

If the dry-run has no unwanted conflicts:

```sh
stow --target="$HOME" --no-folding config bin share
```

If the new machine already has real files at the same paths, do not overwrite them blindly. Either remove/backup those files first, or deliberately adopt them:

```sh
stow --target="$HOME" --no-folding --adopt config bin share
git diff
```

Review any adopted changes before committing them.

### 5. Rebuild the desktop programs

The source code is already installed by Stow under `~/.local/share`. Build each program and install its executable into `~/.local/bin`:

```sh
cd ~/.local/share/vxwm && make && install -Dm755 vxwm ~/.local/bin/vxwm
cd ~/.local/share/dmenu && make && install -Dm755 dmenu stest ~/.local/bin/
cd ~/.local/share/slock && make && install -Dm755 slock ~/.local/bin/slock
cd ~/.local/share/st-terminal && make && install -Dm755 st ~/.local/bin/st
cd ~/.local/share/zlstatus && zig build && install -Dm755 zig-out/bin/zlstatus ~/.local/bin/zlstatus
```

Build `nsxiv` and `vcompmgr` similarly when you use them. The resulting binaries and objects are ignored by `.gitignore` and are recreated on each new machine.

### 6. Activate and verify

Restart the shell or log in again, then check the important links:

```sh
readlink -f ~/.config/zsh/.zshrc
readlink -f ~/.config/x11/xinitrc
readlink -f ~/.local/bin/rvx
readlink -f ~/.local/share/vxwm/config.h
```

Restart the X session to activate the xinit/vxwm configuration. Verify the WM, terminal, launcher, compositor and status bar before removing the backup.

## Maintenance

```sh
cd ~/dotfiles
git pull --ff-only
stow --target="$HOME" --no-folding --simulate --verbose config bin share
stow --target="$HOME" --no-folding config bin share
```

When changing a vendored source tree, rebuild its executable locally and commit only source/configuration changes—not generated objects or binaries.
